# Heuristic Rule Reference

`AI Code Detector Heuristic` exposes six configurable, reviewable code-style signals. Each rule returns matching line indexes and contributes its configured weight once when it matches one or more lines. The module caps the combined score at 100.

| Rule | Default weight | What it checks |
| --- | ---: | --- |
| Explicit AI-tool attribution | 34 | AI-tool names or phrases such as `generated by AI` in a comment. |
| Boilerplate explanatory comments | 13 | Comment openings such as `note:`, `this function`, or `finally,`. |
| Long documentation-style comments | 8 | A comment longer than 72 characters. |
| Highly descriptive identifiers | 7 | Multi-word camelCase declarations with three or more word parts. |
| Repeated adjacent comments | 8 | Two adjacent comment lines. |
| Template-style defensive errors | 6 | `throw` or `raise` statements containing terms such as `required` or `invalid`. |

These are transparent style signals, not a probability or proof of who wrote code. Use them as starting points for human review and replace the default rules when a project needs a different policy.
